# 独立 V1 线上浏览器验收

日期：2026-11-04（Asia/Shanghai）。结论：已部署版本的完整线上业务验收通过；后续 `v1.0.0` 归档已完成，详见[最终交付验收](ACCEPTANCE.md)。下文执行经过保留为本次线上验收证据。

## 目标与方法

- 实际站点：[TaskFlow V1](https://bieyuejie.github.io/taskflow-v1/)。首发提交 `25d83ebff2699e1b99ac8612ae48073be924a118`，成功运行 [41826205389](https://github.com/bieyuejie/taskflow-v1/actions/runs/41826205389)，实际产物及17个静态文件验证见[部署记录](DEPLOYMENT.md)。
- Edge 无头浏览器、原生 CDP、全新临时配置；使用真实线上 HTML/JS/CSS，没有本地 preview 服务器替代线上目标，不连接用户已有窗口，也不修改用户已有浏览器数据。
- 复用四个既有业务验收入口，覆盖1280px、375px、768px。大量数据、存储异常、延迟请求及请求失败通过隔离配置中的夹具和故障注入实现，不进入产品代码；正常新增、编辑、选择、勾选、确认、日历和拖拽均通过实际页面执行。
- 四入口主回归先通过；随后补充未知版本、项目编辑、401、合法空任务及表格滚动，分别通过后，仅将修改过的第四入口完整重跑，确认其懒加载与所有补充场景在同一个浏览器中串行通过。未为新增第四入口场景重复执行已通过的前三入口。
- 线上模式白名单限定上述精确 V1 地址；跟踪真实资源响应、非取消加载错误、JS/CSS MIME 类型和未捕获异常。主回归四入口分别记录88、329、199、168次资源响应，最终第四入口组合运行记录366次；各次运行均无资源错误或未捕获运行异常。
- 完成后关闭本次浏览器，并在校验临时目录绝对路径边界后清理。375px/768px 是桌面 Chromium 视口模拟，拖拽使用鼠标与原生 HTML5 拖放，不声称真实手机触摸设备已验收。

## 脚本修正与边界

- 补充场景第一轮在重置失败后的确认框关闭动画期间再次点击旧按钮，导致等待超时；补上确认框完全关闭的等待，原始失败记录 [ONLINE_EXTRAS_2026-11-04.txt](ONLINE_EXTRAS_2026-11-04.txt) 保留。
- 第二轮将无效Token后的路由拦截误作接口401测试，守卫在接口请求之前已拦截；改为在当前看板选择项目触发受保护查询，实际收到“登录已失效”后确认Token清理和快照保留。该轮记录 [ONLINE_EXTRAS_RETRY_2026-11-04.txt](ONLINE_EXTRAS_RETRY_2026-11-04.txt) 保留，修正后补充及最终组合均通过。
- 以上是验收同步/触发条件修正，没有为此改变业务行为；未隐藏失败记录，不把早期失败误报为当前产品缺陷，也不把构建通过替代实际浏览器验收。
- 保留 V1 纯前端、演示登录、同浏览器单标签页限制；不承诺真实用户隔离、跨设备同步或多标签并发。第五阶段体积改善沿用其同环境记录，不增加加载耗时或真实手机性能声明。
- 本轮线上验收步骤没有创建最终版本标签；后续独立归档步骤已完成 `v1.0.0` 标记，详见[最终交付验收](ACCEPTANCE.md)。

## 复现入口

安装现有锁定依赖后运行 `npm run verify:online`，顺序执行四入口，最后一个包含全部补充场景；线上模式无需先本地构建。需要本机 Edge/Chrome、网络及启动隔离浏览器的权限，常规 CI 的 `npm run check` 不依赖该网络验收。

截图默认按 Asia/Shanghai 当日命名，可用 `TASKFLOW_BROWSER_ARTIFACT_DATE` 指定 YYYY-MM-DD；输出到 stage6，旧阶段截图不覆盖。定向重跑时显式设置 `TASKFLOW_BROWSER_TARGET=https://bieyuejie.github.io/taskflow-v1/`，再运行 `node scripts/verifyLazyRoutesBrowser.mjs --online-extras-only` 或 `--online-tables-only`。
