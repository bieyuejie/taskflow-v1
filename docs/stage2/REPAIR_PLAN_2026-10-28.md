# 第二阶段检查问题修复方案

日期：2026-10-28。范围为用户授权修复检查报告中的8项问题，不提前开发第三阶段功能，不升级依赖。

接口及行为调整先记录如下：

- storageGet 改为 `{ ok: true, value }` 或 `{ ok: false, reason }`，区分不存在和读失败；storageSet、storageRemove 返回明确的成功/失败结果。同步所有调用点。
- repository 初始化区分 ready、损坏、未知版本、读失败及首次写失败；仅键不存在时生成默认快照。候选快照校验和序列化、setItem 全部成功后才发布有效内存。
- 损坏或未知版本期间拒绝任务访问及写入，保留原始数据；重试重新读取。只有显式确认后允许重置，重置写失败仍保留原数据和最近有效内存。
- 增加恢复接口 GET /api/storage/status、POST /api/storage/retry、POST /api/storage/reset。它们只提供本机存储状态与恢复，不返回任务内容；不要求先登录，以便浏览器拒绝存储或启动损坏时恢复。reset 必须携带 confirmed=true，写入失败返回业务400。
- 增加存储状态 store、恢复提示组件，通过 store→API→Mock repository 读取状态、重试或确认重置；组件不直接操作任务存储。存储未准备好时暂停业务页面，保留登录及恢复入口。
- 用户登录先成功保存 V1 Token，再更新登录内存；登录错误可见。守卫、请求层、退出统一使用 V1 键。退出失败反馈到页面，同一页面会话清理内存及任务筛选。
- ID 工具增加已分配ID保留接口；加载合法快照后以项目和任务最大ID恢复生成器，避免重载后时钟回拨碰撞。
- 先加入能复现原问题的故障断言，再实现修复；覆盖真正的setItem失败、原始值保留、首次失败、序列化、确认重置、Token、守卫、重试和重载。

原报告保留为历史检查快照；修复验证结果另存。实际浏览器操作尚须单独验证，不用构建通过代替。
